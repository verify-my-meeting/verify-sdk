# 2026-11-07: protocol spec 2.0, SHA-512 throughout

Decision from `verify-private-docs/14-questions-vmm-vcon.md` Q4: the
protocol hash is SHA-512 everywhere (Merkle leaves and nodes, roots,
commit hashes, payload hashes, profile hashes, batch roots, key ids).
Owner-supplied digests for `link` and `hash` documents may still be
SHA-256 when declared with `hashAlg`; `sha512` is the default. No content
was committed under 1.x, so nothing is migrated.

- `packages/sdk/src/proofs`: `sha512` in `bytes.ts` (SHA-256 kept for PKCE
  and owner digests), Merkle, commit (`v: 2`), signature and receipt
  (`v: 2`) on SHA-512.
- `spec/README.md` 2.0: sections 1, 3, 4, 6, 7, 9, 12; `openapi.yaml` 2.0:
  `hashAlg` on document inputs and records, SHA-512 descriptions.
- `spec/vectors/merkle.json` and `commit.json` regenerated (64-byte roots
  in the sample trees). Canonicalization, segmentation and grade vectors
  are unchanged.
- `DocumentInput.hashAlg` in the SDK types; MCP `add_document` accepts 128-
  or 64-hex digests with `hashAlg`. Packages at 0.3.0.
- Checked that the public OpenTimestamps calendar accepts a 64-byte
  digest (`POST /digest` returned 200), so batch roots are stamped as is.
